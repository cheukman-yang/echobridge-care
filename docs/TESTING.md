# テストと動作確認

## 1. 自動テスト

| コマンド | 内容 | 認証 |
|---|---|---|
| `check.bat`（または `node scripts/dev.mjs check`） | 下の4つをまとめて実行し、最後に結果を一覧にする | 不要 |
| `npm test` | Vitest。サーバー（本物のWebSocket、STTとGeminiは偽物）と画面（jsdom） | 不要 |
| `npm run build` | Next.js の本番ビルド | 不要 |
| `npx tsc --noEmit` | 型検査（`npm run build` の後に実行する） | 不要 |
| `npm run lint` | ESLint。未使用のファイル由来のエラー1件・警告2件は既知（`docs/FEATURES.md`） | 不要 |
| `npm run test:live` | 実際のGeminiを5回呼ぶ | 必要・料金あり |

## 2. 画面で試す

### モックモード（認証不要）

`start-mock.bat` をダブルクリックする。画面（3000番）とモックの通話サーバー（8080番）が起動し、ブラウザで `http://localhost:3000/` が開く。

- 通話の中継（招待、席、再接続、本人確認、読み上げの順番）は本番と同じ処理
- **文字起こしと、返答候補・整形・予定の読み取りは台本**。両方の画面に「開発用のモックモードです」と出る
- 相手が録音すると、マイクの音声の中身に関係なく、台本の次の文が文字起こしとして届く。台本は発信のときの目的（医療機関／日常の連絡）で切り替わる
- 相手の画面ではマイクの許可が必要（音声は使わないが、録音の流れを本番と同じにしている）

モックの結果を、デモ動画や提出物で実際の機能として見せないこと。

### 実APIモード

`start-local.bat` をダブルクリックする。README の「認証と環境変数」（ADC と `.env`）が必要。足りなければ手順を表示し、モックモードで起動するかを聞く。実際の Gemini と Speech-to-Text を呼ぶので料金がかかる。架空の内容だけで試す。

## 3. 2人で試す

相手の画面はマイクを使うので、**HTTPS か localhost でしか録音できない**（ブラウザの制限）。

| 方法 | 本人の画面 | 相手の画面 | 向いている確認 |
|---|---|---|---|
| A. 1台のPCで2つのウィンドウ | `http://localhost:3000/` | 招待リンク（`http://localhost:3000/join#invite=...`）を別のウィンドウで開く | 流れ全体。1人でも2人でも |
| B. 2台（同じLAN） | 別のPCかスマートフォンで `http://<起動したPCのIP>:3000/`（起動時に表示される） | 起動したPCの localhost で開く | 本人の画面のスマートフォンでの操作 |
| C. Cloud Run（HTTPS） | 公開URL | 公開URLの招待リンク | 実機のマイクとスマートフォン。公開の設定が済んでから |

- B では、初回に Windows のファイアウォールの確認が出たら「プライベートネットワーク」を許可する
- 招待リンクをスマートフォンへ送るときは、本人の画面の「リンクをコピー」を使う。B の方法ではリンクの `localhost` を起動したPCのIPに読み替えても、相手の画面はマイクを使えない
- 相手が**タブを閉じると、その通話には戻れない**（招待は応答で使い切る）。再読み込みなら戻れる

## 4. シナリオ

架空の内容だけを使う。モックモードでは相手の発話は台本が自動で入るので、相手役は「押して話す」を押して数秒後にもう一度押すだけでよい。実APIモードでは、相手役が下の文を声に出して読む。

### 医療機関への連絡（約5分）

1. 本人: 目的「医療機関への連絡」、相手の名前「ひまわり医院」、用件「内科の初診予約をしたいです」。あいさつのプレビューを確かめて発信し、招待リンクを相手に渡す
2. 相手: リンクを開いて応答する → あいさつが読み上げられる
3. 相手: 「はい、ひまわり医院受付です。初診のご予約ですね。ご希望の日時はありますか。」
4. 本人: 「明日の午後は空いていますか」と入力し、Enter（AIで整える）→ 案を確かめて「この文を送る」
5. 相手: 「明日の午後2時半でしたらご案内できます。保険の確認のため、マイナンバーカードをお持ちください。」
6. 本人: 返答候補から承諾の文を選ぶ
7. 相手: 「それでは明日の午後2時半にお待ちしております。」
8. 本人: 即答フレーズ「ありがとうございます。」→ すぐに「通話を終了」

確かめること:

- 相手の画面で読み上げられたのは、あいさつ・自動案内・本人が送った文だけ（整形案や候補は、本人が送るまで相手に届かない）
- 本人の画面で、各発言に「AI案を確認」「AI候補から選択」「即答フレーズ」などの経路と、「読み上げ済み」が付く
- 最後の「ありがとうございます。」が、通話の終了後も最後まで読み上げられる
- 予定の下書き: 明日、14:30、場所「ひまわり医院」、メモにマイナンバーカード。「Google カレンダーに追加」で作成画面が開く（保存はしなくてよい）
- 場所の下の「Googleマップで「ひまわり医院」を検索」で地図の検索結果が開く。場所を直すとリンクも変わり、カレンダーの作成画面にも直した場所が入る

### 登録した文（約2分）

1. 発信前の画面の「よく使う文の登録（任意）」を開き、「発話に障害があるため、AIの音声でお話ししています。」を登録する
2. 発信して相手が応答したら、返答欄の「登録した文」で全文が表示されていることを確かめ、「この文を送る」を押す
3. 相手の端末で表示どおりに読み上げられ、本人の記録に「登録した文」と付くことを確かめる
4. 「登録した文を編集」→「すべて削除」で消えること、ブラウザを開き直しても戻らないことを確かめる

- 登録・修正・削除の操作では、相手に何も届かない
- 相手の発話中は「この文を送る」が押せない

### 日常の連絡（約3分）

1. 本人: 目的「日常の連絡」、相手の名前「架空の友人」、用件「土曜日の待ち合わせ時間を決めたいです」で発信
2. 相手: 「もしもし。土曜日の待ち合わせの件だよね。何時にする？」
3. 本人: すぐに即答フレーズ「少々お待ちください。」→ 返答候補が出るまで待たずに送れることを確かめる → 候補か入力で返す
4. 相手: 「じゃあ土曜日の10時に駅前の改札でどう？」
5. 本人: 候補から承諾の文を選ぶ。相手が「通話を切る」

確かめること:

- あいさつが「もしもし。AI音声アシスタントを使ってお話ししています。…」になる
- 予定の下書き: 次の土曜日、10:00、場所「駅前の改札」。相手の名前は場所に入らない
- 予定の話をしない通話（例: 用件「借りていた本のお礼を言いたいです」）では、「予定は見つかりませんでした」と出て、予定の入力を求めない

## 5. 異常系の確認（モックモード）

モックの通話サーバーのURLを、別のタブで開くと切り替わる。終わったら元に戻す。

| 確認したいこと | 操作 | 期待する表示 |
|---|---|---|
| AIの失敗 | `http://localhost:8080/__mock/ai?mode=fail` | 候補が定型文になり「AIの回答ではありません」。整形は「AIで整えられませんでした」。終了後は「AIで予定を読み取れませんでした」と手での追加 |
| AIの遅延 | `http://localhost:8080/__mock/ai?mode=slow` | 約8秒で定型文の候補に切り替わる（予定の読み取りは約20秒） |
| AIを戻す | `http://localhost:8080/__mock/ai?mode=ok` | |
| 音声認識が使えない | `http://localhost:8080/__mock/speech?status=unavailable` | 本人の画面に「音声認識を利用できません」。相手のボタンは「押すと再確認します」 |
| 音声認識を戻す | `http://localhost:8080/__mock/speech?status=ready` | |
| 録音中の認識の失敗 | 録音中に `http://localhost:8080/__mock/speech?fail=1` | 相手の画面に「音声認識が中断しました。もう一度話してください。」 |
| 聞き取れなかった録音 | 相手が「押して話す」をすぐに2回押す | 相手の画面に「声を聞き取れませんでした。相手には何も届いていません。」 |
| 再接続 | 通話中にどちらかの画面を再読み込み | 同じ通話に戻り、会話の記録が戻る。相手の画面は「通話に戻る」を押すと続きを読む |
| 相手の切断 | 相手のウィンドウを閉じる | 本人の画面に「相手の接続が切れています」 |
| リセット | 本人の見出しの「リセット」 | 確認の後、両方の画面が最初に戻る |
| スマートフォンの幅 | ChromeのDevToolsのデバイス表示（375×812）か、方法Bのスマートフォン | 即答フレーズが下端に残り、入力欄と候補をスクロールで操作できる |

## 6. 人が実機で確認すること

自動テストとモックでは確かめられない項目。

1. 実APIモードで、相手の端末のマイクで話した内容が文字になるか（声の大きさ、雑音のある場所）
2. 相手の端末のスピーカーで、あいさつと本人の文が聞こえるか。声の自然さ、速さ
3. 長い文（100文字程度）の読み上げが途中で止まらないか
4. スマートフォン（Android Chrome、iOS Safari）で、相手の画面の「押して話す」がタップと長押しで動くか。長押しで文字の選択やメニューが出ないか
5. iOS Safari で、キーボード表示中に本人の画面の入力欄・確認画面・即答フレーズが隠れないか、日本語入力の確定のEnterでAIの整形が誤って動かないか
6. iOS Safari で、最初の操作の後に読み上げが鳴るか、16kHzでの録音が正しく文字になるか（HTTPSのCloud Runでだけ確認できる）
7. 画面読み上げ（VoiceOver / TalkBack）で、ボタンの名前と状態が読まれるか
