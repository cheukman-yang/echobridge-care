# 機能と検証状況

コードを根拠にした、実装済みの機能の一覧。予定している機能は「今後の拡張」に分けて書く。

状態の見方:

- **実API確認**: 実際の Gemini / Speech-to-Text で動作を確認した（日付と方法を書く）
- **自動テスト**: `npm test` の偽物（STT・Geminiの代わり）で確認している
- **モック確認**: モックモード（`start-mock.bat`）のブラウザ操作で確認した。実際のAIではない
- **未確認**: 人が実機で確かめる必要がある

## 守っている原則

1. **本人が確認していない文は相手に届けない。** 相手に届く文の経路は `server/callRoom.ts` の `speak()` だけで、サーバーは文を書き換えない。AIの返答候補と整形案は本人の画面にだけ送る。例外は、本人が発信前にプレビューで見たあいさつと、入力中の自動案内（固定の文）だけ
2. **AIの結果か定型文かを区別する。** すべてのAIの結果に `source: 'gemini' | 'fallback'` と理由が付き、画面に出る（`src/lib/aiMeta.ts`）。ログにも出所を1行のJSONで出す
3. **AIは事実を作らない。** 本人しか知らないこと（氏名、症状、都合など）は候補に入れず、時間をもらう候補を出すようプロンプトで指示する
4. **通話本文を保存しない。** サーバーのメモリにだけ置き、終了から10分で消す。ログには本文を出さない
5. **予定は自動で確定しない。** 読み取った予定は下書きで、本人が直してからGoogleカレンダーの画面で保存する

## 機能一覧

### 通話の基盤

| 機能 | 内容 | 主なファイル | 状態 |
|---|---|---|---|
| 発信と招待 | 本人が発信すると、10桁の通話コードと招待リンク（`/join#invite=...`）を発行。コードはURLのフラグメントに置き、サーバーのログに残らない。10分で期限切れ | `server/callRoom.ts`、`src/components/CallInviteCard.tsx` | 自動テスト、モック確認 |
| 通話の分離 | 通話ごとの部屋。メッセージは同じ通話の席にだけ届く。役割（本人／相手）と通話の段階をサーバーで確認する | `server/callServer.ts`（`MESSAGE_RULES`） | 自動テスト |
| 再接続 | 席のトークン（タブごとの `sessionStorage`）で同じ通話へ戻る。戻ると会話の記録・候補・読み上げ状態を取り戻す | `src/hooks/useCallChannel.ts`、`snapshotFor()` | 自動テスト、モック確認（本人の再読み込み） |
| 公開URLでの上限 | 同時通話50、接続200、1接続あたり毎分120メッセージ、Geminiは全体で毎分60件、STTの同時録音3本 | `DEFAULT_CALL_LIMITS`、`server/index.ts` | 自動テスト |

### 相手の発話を文字で届ける

| 機能 | 内容 | 状態 |
|---|---|---|
| 押して話す | タップで開始・もう一度で送信、長押しして離しても送信。キーボード（Space / Enter）と支援技術のクリックにも対応。止め忘れは60秒で終える | 自動テスト、モック確認 |
| 文字起こし | Speech-to-Text v1 のストリーミング（ja-JP、16kHz）。途中結果を両方の画面に出し、確定した部分は積み上げる。話し終えた後の最終結果を最大2秒待つ | **実API確認**（2026-11-08、合成音声のファイルを実時間で送る方法。確定は指を離してから約0.1秒） |
| 録音の失敗の通知 | 録音を始められない・認識が止まった・**声を聞き取れなかった**、を相手の画面に出す | 自動テスト、モック確認 |
| 同時録音の枠 | 録音の終了・時間切れ・切断・通話の終了で、STTのストリームを必ず閉じて枠を返す | 自動テスト（`tests/server/sttSlots.test.ts`） |

### 本人が返す

| 機能 | 内容 | 状態 |
|---|---|---|
| 返答候補3つ | 相手が話し終えると、通話の目的・用件・直近12件の会話からGeminiが3つ作る。押すと表示どおりに読み上げる | **実API確認**（2026-11-08、医療・日常で各1回。応答は約1.0〜1.4秒） |
| 定型文の候補 | AIが使えない（未設定・時間切れ・上限など）ときは、目的に合った定型文を「AIの回答ではありません」と明示して出す | 自動テスト、モック確認（時間切れ） |
| 即答フレーズ | 「少々お待ちください。」など6つ。AIを待たず、整形案の確認中や候補の生成中でも送れる | 自動テスト、モック確認 |
| 入力とAIの整形 | 入力した文を、意味・数字・否定を変えずに整える案を出す。本人が案を編集・原文で送る・やめるを選ぶ。数字が変わったら警告 | **実API確認**（否定と数字が保たれることを確認） |
| 入力中の自動案内 | 相手が話し終えて5秒返事がなければ、「通話内容入力中のためお待ちください」を相手に流し、その間は相手の録音を止める | 自動テスト、モック確認 |

### 相手の端末での読み上げ

| 機能 | 内容 | 状態 |
|---|---|---|
| 読み上げ | 本人が確定した文を、相手の端末のブラウザの `speechSynthesis`（ja-JP）で順番に読む。字幕にも出す | 自動テスト、モック確認（読み上げ部分は記録用の偽物）。**実機の音は未確認** |
| 録音との排他 | 読み上げ中は録音できない。録音中に届いた文は録音の後に読む | 自動テスト |
| 終わらない読み上げの打ち切り | 終わりの合図が来なくても、文の長さに応じた時間で止めて次へ進む | 自動テスト |
| 読み上げ状態の報告 | 「送信済み → 読み上げ中 → 読み上げ済み／読み上げられませんでした」を本人の画面に出す | 自動テスト、モック確認、実API通話（報告の往復のみ） |
| 終了時の読み残し防止 | 本人が最後の文を送ってすぐ通話を終えても、届いた文は読み終えてから止まる | 自動テスト、モック確認 |
| 再読み込みの後 | ブラウザが自動再生を止めるので、「通話に戻る」を押してから続きを読む | 自動テスト |

### 通話後

| 機能 | 内容 | 状態 |
|---|---|---|
| 予定の下書き | Geminiが会話から日付・時刻・場所・持ち物を読み取る。合意していない日時や分からない項目は空にし、「要確認」と出す。AIが入れた項目には「AIの読み取り」の印 | **実API確認**（合意した日時・持ち物の読み取り、日時が曖昧な会話・予定の話がない会話で空になること） |
| 予定がない・読み取れないとき | 予定が見つからない、AIが失敗した、を分けて表示し、手で追加できる | 自動テスト |
| Googleカレンダーへ | 日付と開始時刻がそろうと、予定の作成画面（`calendar.google.com/calendar/render`）を開く。保存は本人がその画面で行う | 自動テスト（URLの組み立て） |
| 会話の記録 | 画面を閉じるまで見返せる。サーバーには残らない | 自動テスト |

## Google の技術の使いどころ

| 技術 | 使う場所 | 選んだ理由 | 注意点 |
|---|---|---|---|
| Cloud Run | 画面と通話サーバーを1つのコンテナで配る | WebSocketを最大60分保てる。1サービスなので接続先は同一オリジンで済む | 状態をメモリに置くので最大1インスタンス |
| Vertex AI の Gemini（`gemini-3.5-flash-lite`） | 返答候補、文の整形、予定の読み取り | 応答が約1秒で会話のテンポに合う。サービスアカウントで認証でき、APIキーを配らない。構造化出力（JSONスキーマ）で結果を検証できる | `global` で処理するので、処理場所は日本に限らない |
| Cloud Speech-to-Text v1（ストリーミング） | 相手の発話の文字起こし | 話している途中から文字が出る。日本語に対応 | ストリームは約5分まで。句読点の自動付与は未設定 |
| Googleカレンダー（予定作成URL） | 通話後の予定の保存 | OAuthなしで本人が最後に確認して保存できる。予定を読む権限を持たない | 本人の予定（空き時間）は見ない |

`speechSynthesis` はブラウザの機能で、Google Cloud のサービスではない（Chromeでは「Google 日本語」の声になることがある）。

## 検証の記録（2026-11-08 時点）

| 範囲 | 方法 | 結果 |
|---|---|---|
| 実Gemini | `npm run test:live`（5件）、ローカルの実サーバーへのWebSocket通話（医療・日常で各1回）、予定のない会話の読み取り1回 | すべて `source: gemini`。候補0.95〜1.4秒、整形0.8秒、予定の読み取り0.8〜1.5秒 |
| 実STT | 上の通話で、合成音声のWAV（3秒）を実時間で送信 | 確定は指を離してから約0.1秒。ブラウザのマイクの経路は通していない |
| Cloud Run | 旧版で非公開デプロイと実Gemini・実STTを確認済み | 最新版は未デプロイ |
| ブラウザ2画面 | モックモードで、医療と日常の連絡を発信から予定の下書きまで通した。AIの時間切れ、聞き取れなかった録音、本人の再読み込み、整形案の確認中の即答も確認 | 問題なし（見つけた不具合は修正済み） |
| 未確認 | 実機のマイクと実STTの組み合わせ、読み上げの音質、スマートフォン実機（特にiOS Safari）、最新版のCloud Run、一般公開 | `docs/TESTING.md` の手動確認の項目 |

## 今後の拡張（検討中・未実装）

| 案 | 内容 | 判断材料 |
|---|---|---|
| Cloud Text-to-Speech | サーバーで音声を作り、相手の端末で再生する。失敗したらブラウザの読み上げに戻す | 端末によらず同じ声になる。API の有効化と料金、確定から再生までの遅延を確認してから決める |
