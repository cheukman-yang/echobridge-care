# 機能と検証状況

コードを根拠にした、実装済みの機能の一覧。予定している機能は「今後の拡張」に分けて書く。

状態の見方:

- **実API確認**: 実際の Gemini / Speech-to-Text で動作を確認した（日付と方法を書く）
- **自動テスト**: `npm test` の偽物（STT・Geminiの代わり）で確認している
- **モック確認**: モックモード（`start-mock.bat`）のブラウザ操作で確認した。実際のAIではない
- **未確認**: 人が実機で確かめる必要がある

## 守っている原則

1. **本人が確認していない文は相手に届けない。** 相手に届く文の経路は `server/callRoom.ts` の `speak()` だけで、サーバーは文を書き換えない。AIの返答候補と整形案は本人の画面にだけ送る。例外は、本人が発信前にプレビューで見たあいさつと、入力中の自動案内（固定の文）だけ
2. **AIの結果か定型文かを区別する。** すべてのAIの結果に `source: 'gemini' | 'fallback'` と理由が付き、画面に出る（`src/lib/aiMeta.ts`）。ログにも出所を1行のJSONで出す
3. **AIは事実を作らない。** 本人しか知らないこと（氏名、症状、都合など）は候補に入れず、時間をもらう候補を出すようプロンプトで指示する
4. **通話本文を保存しない。** サーバーのメモリにだけ置き、終了から10分で消す。ログには本文を出さない
5. **予定は自動で確定しない。** 読み取った予定は下書きで、本人が直してからGoogleカレンダーの画面で保存する
6. **会話にない日時や場所をAIに補わせない。** Geminiには日時の根拠になった会話の言葉も抜き出させ、その言葉が会話にあるか、値と矛盾しないかをコードで照合する（`src/lib/appointment.ts`）。合わない値は採用せず、理由を本人に見せる

### 読み上げ音声の改善（Cloud Text-to-Speech）

公式の情報（2026-11-08 確認）:

- Chirp 3: HD は ja-JP に対応（声の名前は `ja-JP-Chirp3-HD-<名前>`、例: Aoede、Kore、Charon など30種）。リージョンは global、asia-northeast1（東京）などでGA
- 一括の合成（MP3、OGG_OPUS など）と、文を送りながら音声を受け取るストリーミング合成（OGG_OPUS、PCM など）がある。話す速さは `speaking_rate`（0.25〜2.0）で変えられる
- 料金: Chirp 3: HD は毎月100万文字まで無料、超えた分は100万文字あたり30米ドル。1回の通話は数百文字なので、デモの範囲では無料枠に収まる見込み
- 遅延は公式に記載がない。実測が必要

小さな検証の方法（`texttospeech.googleapis.com` の有効化が必要。料金は上の無料枠の範囲）:

1. 5つの文（あいさつ、即答、日時、持ち物、自己紹介）を一括で合成し、文を送ってから音声が返るまでを測る。MP3を保存して聞き比べる
2. ストリーミングで、最初の音声が届くまでを測る
3. 判断の目安: 確定から再生開始まで1秒程度に収まり、ブラウザの声より聞き取りやすければ採用する

採用するときの構成案（既存の読み上げ順序・停止・再接続・録音との排他を壊さないことを優先）:

- サーバーは本人の文を今までどおりすぐ相手に送り、並行して音声を作って同じ番号（`seq`）で送る
- 相手の画面は、その文の番が来たときに音声が届いていれば再生し、一定時間（例: 1.5秒）待っても届かなければ、今のブラウザの読み上げに切り替える。どちらで読んだかを本人の画面に知らせる
- 読み上げ中の録音禁止、時間切れの打ち切り、通話の終了時の読み残し防止は、音声の再生にも同じ仕組みを使う
- 再接続で取り戻した文はブラウザの読み上げで読む（音声をサーバーに残さない）

### カレンダーの空き確認（OAuth + freeBusy）

- 本人のブラウザで Google Identity Services のトークンモデル（`google.accounts.oauth2.initTokenClient`）を使い、`https://www.googleapis.com/auth/calendar.freebusy` だけを許可してもらう
- ブラウザから `POST https://www.googleapis.com/calendar/v3/freeBusy` を呼ぶ。返るのは予定がある時間帯だけで、予定の題名や中身は返らない
- 相手が提案した日時はGeminiが文から取り出し、重なりの判定は freeBusy の結果だけで行う（AIに推測させない）
- Geminiには「その時間は空いている／重なっている」だけを渡し、返答候補に反映する。本人の予定の中身は渡さない
- 人が行う準備: Google Calendar API の有効化、OAuth同意画面（外部・テスト中、テストユーザーの追加）、OAuthクライアントID（ウェブアプリ、承認済みのJavaScript生成元に Cloud Run のURLと `http://localhost:3000`）。クライアントIDは `NEXT_PUBLIC_GOOGLE_OAUTH_CLIENT_ID` としてビルド時に渡す
- 注意: カレンダーのスコープは機密性の高いスコープに当たり、審査前のアプリは警告画面が出て、テストユーザーしか使えない。審査員に試してもらうには、テストユーザーへの追加が必要
- 今は簡易版として、本人が自分でGoogleカレンダーを開いて確かめるリンクだけを置いている
