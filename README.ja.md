## 1. プロジェクト概要（Overview）

**EchoBridge Care** は、構音障害・吃音・喉頭摘出・難聴などにより「電話での発話・聞き取りや診察室での口頭コミュニケーション」に困難を抱える方や、言語の壁がある外国人患者（および海外滞在中に英語で受診する日本人患者）を、**受診前の電話予約から診察後の再診管理まで一気通貫で支援する医療アクセシビリティ＆バイリンガル対話Webアプリケーション**です。

従来の翻訳アプリや読み上げツールが「その場限りの単発機能」にとどまっていたのに対し、EchoBridge Care は患者の受診ジャーニー全体を1つのブラウザ上でシームレスに繋ぎます：

1. **病院検索・AI予約電話（`/`）**：症状や希望エリアを整理して適切な診療科・候補病院を見つけ、合成音声（TTS）・AI 3択回答候補・登録文を使ってブラウザ内で予約通話を完結。
2. **経路案内・来院引き継ぎ**：予約確定後に Google Maps 経路案内・周辺地図を表示し、到着後は保存された予約情報を持ってワンタップで対面診察モードへ移行。
3. **机上平置き180度反転「対面診察モード」（`/consult`）**：診察室の机にスマートフォンを平置きし、上半分を医師向けに180度反転表示・下半分を患者向け正立表示にする非対称UXとリアルタイム日英通訳で円滑な筆談・音声対話を実現。
4. **構造化医療サマリー＆再診カレンダー登録**：診察会話から主訴・所見・処方・療養指示を構造化箇条書きに自動要約し、会話根拠に基づく再診日時・病院住所を Google Calendar へワンタップ登録。

全画面で **日本語 / 英語（`🇯🇵 日本語` / `🇺🇸 English`）の即時UI切り替え**、次に押すべきボタンを直感的に示す **インタラクティブ視覚誘導（シマー閃光＋マイクロ振動）**、そして `.env` 設定不要ですぐに全機能を体験できる **ローカルデモ応答モード** を備えています。

## 2. 主な機能と非対称UX設計（Key Features & Asymmetric UX Design）

### 🏥 4ステップ AI 模擬予約通話（`/` — 予約ウィザード）
- **Step 1 — 症状・希望エリア・出発地の入力**：
  - 主訴・希望診療科・希望エリア・経路案内の出発地・第1〜第3希望日時を入力。
  - **`例を入力`** ボタン（主訴に加え、希望エリア「`新宿駅周辺`」・出発地「`新宿駅`」まで同時自動入力し、GPSを使わない審査環境でも経路案内まで完走可能）と、入力メモを丁寧な医療表現へ整えつつ後から自由に手直しできる **`✨ AIブラッシュアップ`** ボタンを搭載。
- **Step 2 — AI診療科トリアージ＆模擬クリニック選択**：
  - 症状の整理結果・推奨診療科・候補クリニックを表示し、最上部に **`[審査・検証用] EchoBridge Care 模擬クリニック`** をピン留め配置。外部電話網（PSTN）へ発信せず安全にブラウザ内で予約通話を検証できます。
- **Step 3 — 開始用件の確認＆デフォルト1件プリセット付き登録文**：
  - Step 1・2 の入力内容から最初の挨拶・希望日時文を自動生成し、合成音声（女性／男性）を選択可能。
  - 初回アクセス時（`localStorage` 未保存時）から **デフォルト登録文1件**（「*発話や聞き取りにサポートが必要なため、AI音声と画面表示でお話ししています。ゆっくりお話しいただけると助かります。*」）を自動プリセット。目立つ **`[✅ 登録文を確定してリストに追加]`** ボタンに加え、確定を押し忘れたまま通話を開始しても未確定テキストを自動保存します。
- **Step 4 — リアルタイム AI 模擬受付通話 ＆ 2ページ分割完了画面**：
  - 日本語TTS読み上げ（英語UI時は英訳字幕付き）、開閉式の **「💡 AI3択回答候補」ドロワー**、右スワイプ誘導付きの **常時表示「即答フレーズ」バー** と **「📌 登録文（N件）」トグル** の分離表示、および英語UIでも入力欄が潰れない **2段ワイド自由入力欄**（上段：`w-full` テキスト入力 ／ 下段：`[🎤 音声入力 | ✨ AI整形 | 📤 送信]`）を搭載。
  - **完了ページ 1（病院への経路案内）**：予約内容を端末内に自動保存し、架空ビル名を排した同一の実在駅・住所ランドマークを用いて **Google Maps 経路案内** と **周辺地図** を整合表示。
  - **完了ページ 2（カレンダー登録＆対話ログ）**：**Google Calendar** への予約登録、折りたたみ式の予約通話ログ確認、および **`🩺 病院に着いたら：このまま「対面診察モード」を開く（予約情報を引き継ぐ）`** ボタンを配置。

### 🩺 机上平置き 180度反転「対面診察モード」（`/consult`）
- **コンパクトな診察前準備 2ステップ**：
  - **準備 Step 1**：対話言語ペア（`🇯🇵 JA ⇄ JA` / `🌐 患者: English ⇄ 医師: 日本語` / `✈️ 患者: 日本語 ⇄ 医師: English`）の選択と、保存済み予約記録からのワンタップ引き継ぎ。
  - **準備 Step 2**：症状・アレルギーメモの確認（`例を入力` / `✨ AIブラッシュアップ` 対応）と登録文の事前確認。
- **医師側 × 患者側の非対称スプリットUX設計**：
  - **医師側エリア（画面上部 1/3・机向かいから読める `180°` 反転表示）**：
    - 患者が確定したメッセージを医師の言語で大きく高コントラスト表示し、ワンタップ音声再生に対応。
    - 診察室での環境音・カルテ打鍵音の誤録音を防止するため、**Push-to-Talk（押している間だけ録音）** 方式を採用。さらに中央アクションバーの **`🤖 次の質問(デモ用)`** ボタンにより、審査員1人・1台の端末でも医師の問診〜所見〜処方〜再診指示までリアルに進行可能。
  - **患者側エリア（画面下部 2/3・正立表示）**：
    - 文脈が一目で見渡せる **LINE/WhatsApp風の吹き出し会話タイムライン**（左：医師発言＋翻訳、右：患者発言・自動スクロール）を採用。
    - 開閉式 **AI 3択回答ドロワー**、右スワイプ対応 **即答フレーズバー** ＋ **`📌 登録文`** トグル、そして **2段ワイド自由入力欄**（上段：`w-full` 入力欄 ／ 下段：トグル式 **`🎤 音声入力`** ＋ インプレース再編集可能な **`✨ AI整形`** ＋ 本人確認後に表示する **`📤 医師へ表示`**）を備えています。

### 📋 診察後の構造化医療サマリー ＆ 根拠ベース再診カレンダー登録
- **臨床構造化サマリー**：診察終了時に単なる会話抜粋や医師の質問文を除外し、**① 主訴・相談内容**、**② 診察の要点（所見・既往／アレルギー）**、**③ 処方・今後の療養指示・次回受診目安** の3項目に構造化した日英サマリーを自動生成。
- **会話根拠に基づく厳密な再診日時抽出**：会話内で具体的な時刻への言及がない場合は勝手な時刻を捏造せず **終日予定（All-Day Event）** として Google Calendar URL を生成し、時刻言及がある場合はその時刻を自動セット。医療機関名と編集可能な **医療機関住所** も `location` パラメータへ反映します。
- **トップ画面の履歴連携（`📋 過去の予約・受診記録`）**：トップハブ下部に保存件数と最新履歴プレビューをコンパクトに表示し、展開すると過去の予約・受診サマリー確認およびワンタップでの **「再予約へ」「対面診察へ」** 引き継ぎが可能です。

### 🔒 プライバシー重視のローカル保存 ＆ APIキー不要のローカルデモ応答モード
- **サーバー永続保存ゼロ（Privacy-First `localStorage`）**：症状メモ・通話ログ・受診要約・予約履歴・登録文などの機微な医療情報はすべて **端末内のブラウザ `localStorage` のみ** に保存され、外部データベースへ永続保存されません。
- **4秒タイムアウト＆即時ローカルデモフォールバック**：全AI APIに最大4秒のタイムアウト保護を設け、Gemini APIキー未設定時やオフライン時は医療シナリオに即したローカル応答エンジンへ即座に切り替わります（ヘッダーの `Gemini Live AI` / `ローカルデモ応答モード` バッジで常時明示）。
- **ブラウザ間リアルタイムWeb通話（`/join`）**：2台のブラウザを WebSocket でつなぐ招待リンク式のライブ通話ルーム（`/join`）も引き続き利用可能です。

## 3. クイックスタート ＆ 審査員向け最短2分デモ手順（Quick Start & Judge Walkthrough）

### クイックスタート（`.env`・APIキー設定不要）

```bash
# 1. 依存パッケージのインストール
npm install

# 2. 開発サーバーの起動（APIキー未設定でも自動的にローカルデモ応答モードで全機能が動作します）
npm run dev
```

ブラウザ（Chrome / Edge / Safari 推奨）で **`http://localhost:3000`** を開いてください。  
*（`.env.local` の作成やクラウド認証・ログインなしで、すべての画面と機能をそのまま検証いただけます。）*

---

### ⏱️ 審査員向け：最短2分通しデモ手順

各画面で **ティール色に光って微振動するボタン（シマー＆マイクロ振動誘導）** を順にタップしていくだけで、1台のPCまたはスマートフォンで約2分間に全フローを完走できます：

#### 前半：病院検索・AI予約電話 〜 経路案内（`/` — 約1分）
1. **トップハブ（`/`）**：上部で言語（`🇯🇵 日本語` または `🇺🇸 English`）を選び、光っている **`🏥 病院を探す・AIで予約電話する`** をタップ。
2. **Step 1/4（症状・希望条件）**：**`例を入力`** をタップすると、主訴・診療科・希望エリア（`新宿駅周辺`）・出発地（`新宿駅`）が一括入力されます（任意で **`✨ AIブラッシュアップ`** を押すと医療表現への整形と自由編集も試せます）。そのまま **`次へ：候補の病院を探す`** をタップ。
3. **Step 2/4（候補クリニック選択）**：最上部にピン留めされた **`[審査・検証用] EchoBridge Care 模擬クリニック`** の **`この模擬クリニックを選んで通話準備へ`** をタップ。
4. **Step 3/4（通話前の確認）**：自動生成された最初の用件と、最初から1件プリセットされている「よく使う文」を確認し、**`AI模擬受付へ予約電話をかける`** をタップ。
5. **Step 4/4（AI模擬受付との通話）**：
   - AI模擬受付からの応答と提案日時を確認します。
   - **`💡 AI3択回答候補を開く（3件） ▲`** からワンタップ返信するか、**`📌 登録文（1件）`**・右スワイプ **即答フレーズ**・下部の **2段ワイド入力欄**（`🎤 音声入力` / `✨ AI整形` / `📤 送信`）を試します。
   - **`通話を終了して予約・経路を確認`**（または右上の `通話終了・予約確認`）をタップ。
6. **完了ページ 1 ➔ 2**：
   - **完了 1/2**：出発地「`新宿駅`」が反映された **`Google Maps で病院への経路案内を開く`** と **`周辺地図を確認する`** を確認し、**`[次へ：Google Calendar 予約登録へ進む →]`** をタップ。
   - **完了 2/2**：**Google Calendar** 登録プレビューと折りたたみ式の対話ログを確認し、最下部の **`🩺 病院に着いたら：このまま「対面診察モード」を開く（予約情報を引き継ぐ）`** をタップ。

#### 後半：180度反転「対面診察モード」〜 構造化要約・再診登録（`/consult` — 約1分）
1. **準備 Step 1/2**：先ほどの予約記録が選択されていることと対話言語ペア（例：`🇯🇵 JA ⇄ JA` や `🌐 EN ⇄ JA`）を確認し、**`次へ：症状メモ・登録文の確認`** をタップ。
2. **準備 Step 2/2**：引き継がれた症状メモと登録文を確認し、**`🩺 対面診察を開始する（上下反転画面へ）`** をタップ。
3. **対面診察中（上下180度分割画面）**：
   - 上部の **180度反転した医師側パネル**（誤録音防止の `押している間だけ録音` ボタン付き）と、下部の **吹き出し会話タイムライン**（初回問診が自動表示済み）を確認します。
   - **`💡 AI3択回答候補を開く ▲`** または2段ワイド入力欄（入力 ➔ **`✨ AI整形`** ➔ **`📤 医師へ表示`**）で返答すると、上部の医師側180度カードが即座に更新されます。
   - 中央バーの **`🤖 次の質問(デモ用)`** を1〜2回タップし、診察所見・処方・2週間後の再診案内まで進めます。
   - **`✅ 診察終了・要約へ`** をタップ。
4. **診察サマリー＆再診カレンダー登録**：
   - 構造化された **「1. 主訴」「2. 診察の要点（所見・アレルギー）」「3. 処方・療養指示」** を確認。
   - 自動抽出された **2週間後の再診日・時刻・医療機関住所** を確認し、**`Google Calendar に再診予定を登録する`** を試します。
   - **`トップへ戻る`** を押すと初期2択ハブ画面へクリーンに復帰し、下部の **`📋 過去の予約・受診記録`** から保存された予約・受診履歴をいつでも確認・再利用できます。

## 5. 実AI連携・デプロイ設定（任意）

本アプリは環境変数なしでもローカルデモ応答モードでそのまま動作します。実環境の **Gemini API** や **Google Cloud Text-to-Speech** を有効にする場合は、プロジェクト直下に `.env.local`（または `.env`）を作成してください。

### 方法 A：Gemini Developer API キーを使う場合（最も手軽）
```ini
GEMINI_API_KEY=your_gemini_api_key_here
```

### 方法 B：Google Cloud Vertex AI + Cloud TTS を使う場合（ADC / Cloud Run）
```bash
gcloud auth application-default login
gcloud auth application-default set-quota-project <プロジェクトID>
```
```ini
GOOGLE_GENAI_USE_VERTEXAI=true
GOOGLE_CLOUD_PROJECT=your_gcp_project_id
GOOGLE_CLOUD_LOCATION=global
# Cloud TTS を使わずブラウザ標準音声のみにする場合は TTS_ENABLED=false
```

### 本番起動（Cloud Run 対応単一ポート構成）
```bash
npm run build
NODE_ENV=production npm start
```
